# База поставщиков и технических знаний для серверного агента

Подготовлено 23 октября 2026. Дополнение к уже работающему агенту: источник → модель/артикул → документ → факт → сверка требования.

| Содержимое | Количество |
|---|---:|
| Источники поставки и бренды | 76 |
| Маркетплейсы и другие каналы | 12 |
| Технические источники производителей/брендов | 89 |
| Документы и страницы моделей в реестре | 33 |

Эти группы пересекаются: один производитель может быть поставщиком и техническим источником. Это не число независимых юридических лиц. 1 запись Lenovo MTM пока содержит только идентичность и ссылку, без извлечённых характеристик; её JS-страница не выдана за заполненные карточки. У AMD Tray собственных фактов нет, общие подтверждённые свойства берутся из связанного семейства. Не все зарегистрированные документы удалось прочитать. Статусы и причины доступны в данных.

## Что передать Quod

Передайте весь архив и попросите начать с `QUOD_TASK.md`. Внутри уже есть готовая `knowledge.sqlite`, исходные JSON/JSONL и инструменты. Задание сохраняет действующий поиск, память источников и обученные приоритеты.

## Посмотреть без сервера

Нужен Python 3.10+ с SQLite/FTS5. Внешние библиотеки и ключи для локальной базы не требуются.

```bash
python tools/kb.py lookup 'SNV2S/1000G'
python tools/kb.py card kingston_nv2_1000
python tools/kb.py sources --category cartridges --kind supplier
python tools/kb.py compare kingston_nv2_1000 tests/example-request.json
python tests/test_kb.py
```

В контрольном примере SSD 1000 GB проходит ёмкость, не проходит заданную максимальную скорость записи 2800 MB/s, а тип NAND TLC остаётся неподтверждённым: `pass / mismatch / unknown`. Это синтетические требования, не ТЗ пользователя.

Точный поиск не склеивает `TL-5120H` и `TL-5120HP`, `12400` и `12400F`, DDR4/DDR5, разные ёмкости и аппаратные ревизии. Результат `suggest` — только кандидаты, не доказательство идентичности.

## Где лежат данные

- `SUPPLIERS.md` — читаемый список поставщиков и доступов.
- `TECHNICAL_SOURCES.md` — технические каталоги, поддержка, документы и статус чтения.
- `MODEL_FACTS.md` — фактически извлечённые значения с основаниями.
- `data/suppliers.json` — источники поставки, категории, URL, ограничения, ссылки на API.
- `data/technical-sources.json` — маршруты поиска спецификаций и паспортов.
- `data/models.json`, `facts.json`, `documents.json`, `compatibility.json` — нормализованные сущности; рядом JSONL.
- `data/technical-profiles.json` — подсказки для 13 технических групп; мебельные профили сохранены отдельно.
- `data/search-policy.json` — порядок чтения, обновления, бесплатные приоритеты и ограничения.
- `docs/schema.sql`, `docs/contract-example.json` — структура и контракт для адаптера.
- `research/validation.json` — фактическая локальная проверка; `research/retrieval-index.json` — журнал исследованных ссылок.

## Что проверено, а что предстоит

Проверены публичные источники, вручную сверены сохранённые факты, пройдены 40 тестов эталонного модуля и проверки целостности SQLite. Локальная повторная выдача использует ноль сетевых запросов. Это не замер ускорения сервера и не полный прогон реальной закупки. Доступы к партнёрским API, фактические оптовые цены, остатки и доставка не проверялись. Товарные предложения и текущий код платформы в эту работу не передавались.

Основной следующий прирост объёма даст загрузка разрешённых партнёрских каталогов и сохранение моделей из реальных закупок. База источников сама по себе не создаёт миллионы паспортов: пакет даёт заполненное начало, маршруты, структуру и проверенный локальный механизм повторного использования.

100% — критерий подтверждения всех обязательных требований конкретного ТЗ, а не обещание найти отсутствующие в публикациях сведения. Неизвестные и противоречивые поля сохраняются явно и запускают дальнейший поиск.

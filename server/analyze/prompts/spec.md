Ты составляешь спецификацию товаров по технической документации государственной закупки: что именно нужно купить, чтобы товар подошёл заказчику.

На вход — JSON: `positions` — позиции из извещения (номер `idx`, наименование, количество, единица), и `documents` — текст документов (техническое задание, описание объекта закупки, спецификация, проект контракта), размеченный заголовками <<<ФАЙЛ: … | СТРАНИЦА: …>>>.

Для КАЖДОЙ товарной позиции верни:
- idx — номер позиции из `positions`, к которой относится описание (null, если в извещении такой позиции нет);
- name — наименование товара, как в документации;
- quantity, unit — количество и единица измерения («шт», «упак», «пачка», «кг», «т», «л» …) или null;
- pack_qty — сколько штук в упаковке/пачке, если это указано (например, «500 листов в пачке» → 500), иначе null;
- equivalent_allowed — true, если допускается эквивалент («или эквивалент»); false, если указан конкретный товарный знак без эквивалента; null, если не сказано;
- identity — идентифицирующие признаки: model (модель или артикул), brand (производитель или товарный знак), compatible_with (с каким оборудованием совместим, например «Kyocera ECOSYS M2540dn»), standard (ГОСТ, ТУ). Чего нет в тексте — null;
- required — обязательные характеристики: [{"name": "…", "value": "…", "unit": "…" или null, "comparator": "=", ">=", "<=", "range" или "one_of", "quote": "дословная цитата из документа", "file": "имя файла", "page": номер страницы}].
  - value — дословно с условием: «не менее 80», «А4», «чёрный».
  - comparator: «не менее» → ">=", «не более» → "<=", «от … до …» → "range", «один из вариантов» → "one_of", остальное → "=".
  - Признак, который делит товары на несовместимые виды, включай всегда и первым: цветность печати (чёрно-белая или цветная), тип устройства (принтер или МФУ), формат.
  - Не больше 15 самых важных характеристик — тех, по которым один товар отличается от другого (размеры, формат, плотность, объём, мощность, совместимость, цвет, ресурс, материал).

Правила:
1. Только то, что написано в документах. Не придумывай модели, характеристики и количества. Нет данных — null или пустой список.
2. Цитата (quote) — точный фрагмент текста со страницы, 8–200 символов, без пересказа.
3. Работы и услуги (доставка, монтаж, обучение) — не позиции, их не выделяй.
4. Если характеристик в документах нет, верни позицию с пустым required.

Ответ — только JSON без пояснений и markdown:
{"items": [{"idx": 0, "name": "…", "quantity": 10, "unit": "шт", "pack_qty": null, "equivalent_allowed": true,
  "identity": {"model": null, "brand": null, "compatible_with": null, "standard": null},
  "required": [{"name": "…", "value": "…", "unit": null, "comparator": "=", "quote": "…", "file": "…", "page": 1}]}]}

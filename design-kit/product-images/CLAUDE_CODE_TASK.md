# Claude Code: внедрить изображения товаров в Tender AI

## Цель и готовый результат

Заменить маленькие условные иконки товаров полноценными изображениями категорий из этого комплекта. Дизайн — выбранная пользователем «Медь»: тёплый светлый фон, реалистичные материалы, мягкие тени. Все изображения уже созданы. Генерировать их повторно или искать фотографии в интернете не требуется.

Комплект содержит 72 изображения: 71 предметная категория и «Прочие товары». В папке assets есть WebP 320×320 для списков и 768×768 для крупных карточек. Исходники PNG 1254×1254 предоставлены отдельным архивом и для работы интерфейса не нужны.

Внедри изменения в существующий проект, сохраняя его стек, маршруты, API и работающие функции. Сначала прочитай локальные инструкции проекта и проверь актуальную структуру репозитория. Это задача на отображение изображений, а не переработка поиска поставщиков или анализа тендеров.

## 1. Найти правильные места подключения

В ранее доступной копии проекта:
- public/index.html содержит карточки предложений .pcard и изображения .pimg.
- Для предложения используется o.image_url. При ошибке встречался обработчик onerror="this.parentNode.remove()". Замени этот сценарий на корректную подстановку иллюстрации, сохранив карточку и ссылку на товар.
- .tzphotos выводит реальные изображения, извлечённые из тендерной документации.
- server/tenders/photos.js содержит createPhotoService, ensurePhotos, photoForItem и привязку фотографий к item_idx. Эти фотографии используются при поиске моделей и поставщиков.

Это ориентиры по старой копии, а не утверждение о текущей версии сервера. Найди актуальные компоненты и адаптируй подключение к ним. Не заменяй проект другим шаблоном и не создавай второй набор карточек рядом с действующими.

## 2. Разместить файлы

1. Скопируй содержимое assets/ в каталог статических ресурсов проекта, например public/assets/tender-products/.
2. Размести catalog.js, product-images.js и product-images.css в принятом для проекта месте.
3. Для обычного HTML сначала загрузи catalog.js, затем product-images.js. Модуль не требует npm-зависимостей или внешнего CDN.
4. В сборщике используй существующий способ импорта. При необходимости адаптируй UMD-обёртку к ESM, сохранив алгоритм и проверки.
5. Не подключай изображения как base64 в основной JS-бандл. Используй отдельные статические URL.
6. Назначь assetBase в соответствии с реальным URL раздачи ресурсов. Учитывай размещение приложения в подкаталоге.
7. Не публикуй ZIP и PNG-оригиналы как обязательные ресурсы каждой страницы.

## 3. Приоритет изображения

Приоритет:
1. Реальная фотография, уже связанная с текущим товаром/предложением: поставщик, производитель либо конкретная позиция ТЗ.
2. Иллюстрация категории, выбранной пользователем вручную.
3. Иллюстрация по известному categoryId из каталога.
4. Осторожное сопоставление по названию.
5. Нейтральное изображение generic_supply_box.

Не подставляй случайную картинку при нескольких подходящих категориях. resolve() возвращает selection.reason и candidates; используй их при ручном выборе категории. Настройки иллюстрации не меняют юридическую классификацию товара, его ОКПД2 или результаты проверки ТЗ.

Подбор по названию — небольшой расширяемый словарь, а не универсальный классификатор. Он специально пропускает неоднозначные слова и учитывает границы слов. Пополнение словаря должно сопровождаться проверкой конфликтов. Например:
- «картридж для принтера» → картриджи;
- «картридж для фильтра воды» → нейтральная категория;
- «монитор пациента» → медицинское оборудование;
- «кронштейн для монитора» → нейтральная категория;
- «серверный шкаф» → серверы;
- «шина медная электрическая» → нейтральная категория;
- «ноутбук и коммутатор» → неоднозначный набор, нейтральная категория;
- явный itemKind=service или work → без предметной иллюстрации.

Если наименование — модель без типа товара, используй известную категорию товара либо ручной выбор. Не пытайся угадать тип по одному артикулу.

## 4. Контракт готового модуля

TenderProductImages.resolve(item, options) возвращает primary, fallback, selection.
TenderProductImages.createFigure(item, options) создаёт безопасный DOM-элемент figure с изображением, подписью и обработкой ошибки.

Поля item:
- name: название текущей товарной позиции.
- itemKind: product, service или work.
- categoryId: существующий ID из catalog.json, если он известен.
- manualCategoryId: ID, выбранный пользователем, если есть.
- realImages: массив объектов {url, kind}; kind — supplier, manufacturer или tz.

Порядок realImages определяет приоритет реальных фотографий. Передавай только фотографии, связанные именно с данной позицией. Модуль проверяет схему URL, но не устанавливает соответствие фотографии модели или источник её происхождения. Эту связь берём из существующей модели данных.

Поля options:
- assetBase: URL папки, внутри которой лежат 320/ и 768/.
- sizes: CSS-описание ширины картинки для srcset; адаптируй к реальной карточке.
- allowHttp: по умолчанию false. Не включай на HTTPS-сайте ради внешних старых ссылок: при недоступном фото отображается локальная иллюстрация. Если в проекте уже есть безопасный прокси изображений, сохрани его.

Пример адаптера после проверки реальных полей проекта:

    const media = TenderProductImages.createFigure({
      name: item.name,
      itemKind: "product",
      categoryId: item.categoryId,
      manualCategoryId: item.manualCategoryId,
      realImages: offer.image_url
        ? [{ url: offer.image_url, kind: "supplier" }]
        : []
    }, {
      assetBase: "/assets/tender-products",
      sizes: "(max-width: 600px) 45vw, 240px"
    });
    mediaSlot.replaceChildren(media);

Это пример интерфейса, а не основание считать item.categoryId существующим полем БД. Сделай адаптер к актуальной схеме. Используй createElement/textContent либо безопасные механизмы текущего фреймворка; не вставляй названия товаров и URL в неэкранированный HTML.

При использовании React/Vue можно использовать resolve() внутри собственного компонента. Повтори обработку ошибок из createFigure(): реальное фото → иллюстрация категории; ошибочная иллюстрация → нейтральная; при следующей ошибке — устойчивое пустое состояние, без бесконечных повторов и удаления карточки.

## 5. Сохранить происхождение данных

Иллюстрации имеют sourceType=ai_category_illustration, exactProductPhoto=false.

Обязательные правила:
- Не записывать их в коллекцию фотографий ТЗ или фото поставщика.
- Не передавать их в обратный поиск по картинке, распознавание модели, сопоставление портов/характеристик и подбор эквивалента.
- Не использовать их как доказательство соответствия тендеру, регистрационное удостоверение, сертификат или часть заявки.
- Не заменять оригиналы документов или извлечённые фотографии.
- Не присваивать картинке автоматически бренд, модель, цену, наличие или страну происхождения.
- Показывать подпись «Иллюстрация категории» и доступное описание «не фото конкретной модели».
- В реальной фотографии сохранить подпись источника и связь с товаром.
- Иллюстрация категории не должна увеличивать уверенность анализа или менять оценку риска тендера.

Категории укрупнённые. Например, «Кухонное оборудование» изображено печью, а «Сантехника» — раковиной. Это обозначение раздела, а не внешний вид каждого входящего в него товара. Для узких товарных карточек при необходимости назначай нейтральную иллюстрацию или добавляй новую конкретную категорию.

## 6. Отображение и производительность

- Предметные изображения показывать отдельно от текста, а не как фон под ценой и характеристиками.
- Использовать object-fit: contain; не обрезать предмет через cover.
- Сохранять квадратное соотношение сторон, фиксированные width/height для отсутствия скачков макета.
- Для строки списка достаточно 64–96 CSS px; для карточки — примерно 180–280 CSS px. Изображение в развёрнутой карточке может быть крупнее.
- В маленьких списках использовать 320 WebP, в крупных — 768, выбирать через srcset/sizes. Не загружать PNG по умолчанию.
- loading=lazy, decoding=async для изображений ниже первого экрана. Не делать общий preload всех 72 категорий.
- Подпись иллюстрации должна быть различима и на мобильном экране. Не прятать её только в hover.
- Фон изображений непрозрачный, тёплый светлый. В тёмной теме сохрани светлую область предмета и согласуй рамку с темой. Не инвертируй цвета самого изображения.
- Ссылку на предложение размещай на карточке/кнопке по реальному offer.url. Изображение категории само по себе не является ссылкой на поставщика.
- Если показываешь только декоративный дубль рядом с уже полностью доступной подписью, можно использовать пустой alt. В основном компоненте описание категории уже задано.
- Существующую CSP сохраняй. Для локальных WebP достаточно уже используемой раздачи статических изображений; не ослабляй политику ради произвольных схем URL.

## 7. Ручной выбор и расширение

Если в проекте уже есть редактирование товара, добавь туда выбор иллюстрации категории. Сохраняй manualCategoryId отдельно от фактической категории/ОКПД2. Привяжи выбор к устойчивому ID товара, а не к номеру строки на странице.

Не добавляй отдельную БД только ради картинок. Если подходящего хранилища метаданных ещё нет, сначала внедри отображение и поддержку явно переданного categoryId; укажи в отчёте, что сохранение ручного выбора требует отдельного подключения.

Для новой категории:
1. Выбрать уникальный ASCII ID.
2. Добавить изображение в том же стиле, экспортировать 320/768 WebP.
3. Обновить catalog.json и catalog.js синхронно, добавить alt и метаданные происхождения.
4. Добавить узкие ключевые фразы и отрицательные случаи в тесты.
5. Убедиться, что старые категории не перестали распознаваться.
6. Сохранить запрос генерации. Не изменять существующие ID при переименовании русской подписи.

generation-prompts.json содержит точные запросы текущих изображений. Использован встроенный image_gen.imagegen, каждое изображение создано отдельно; WebP — технические производные исходных PNG, без ретуши и коллажирования.

## 8. Проверка и завершение

Запусти встроенные проверки:
    node --test tests/resolver.test.cjs

В проекте дополнительно проверить:
1. Камера, коммутатор, ноутбук, видеорегистратор получают подходящие иллюстрации без реального фото.
2. Мебель, стройматериалы, бумага, инструменты, запчасти и прочие группы доступны.
3. Реальная фотография поставщика имеет приоритет.
4. Фото из ТЗ остаётся оригиналом и продолжает использоваться существующим поиском.
5. Битый внешний URL заменяется локальной картинкой, а не удаляет карточку/ссылку.
6. Битый локальный ресурс не вызывает бесконечный цикл.
7. Неизвестный товар и неоднозначный набор получают нейтральное изображение.
8. Услуги и работы не получают случайную товарную картинку.
9. На ширинах 390, 768 и 1440 px карточки не вызывают горизонтальный скролл.
10. Нет новых ошибок JS, отсутствующих файлов и тяжёлой массовой загрузки изображений.
11. Поиск, фильтры, цены, расчёт прибыльности, анализ документов и маршрутизация работают как раньше.
12. Все сгенерированные изображения помечены как иллюстрации категорий.

В конце перечисли изменённые файлы, места внедрения и результаты проверок. Приложи скриншоты карточек на широком и мобильном экране. Отдельно укажи, какие изменения готовы в коде и что фактически развёрнуто. Не утверждай, что опубликовано, если развёртывание не выполнялось.

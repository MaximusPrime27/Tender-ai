# Задание: новый дизайн веб-сервиса tender-ai

Ты — веб-дизайнер и верстальщик. Нужно переработать внешний вид сервиса **tender-ai**: он помогает предпринимателю находить выгодные госзакупки и коммерческие тендеры, читать техническое задание (ТЗ) и находить поставщиков дешевле, чтобы заработать на разнице цен. Пользователь — новичок в закупках, работает с сервисом каждый день, на компьютере и иногда с телефона.

## Что приложено

- `styles.css` — все текущие стили сервиса (единственный файл, который ты меняешь).
- Снимки страниц с настоящей разметкой — открой их в браузере рядом со `styles.css`, чтобы видеть результат:
  - `1-lenta.html` — лента закупок (главный экран): фильтры, карточки закупок с оценкой 0–100, ценой, сроком, прибылью.
  - `2-kartochka-zakupki.html` — карточка закупки: выгодность, позиции и требования ТЗ, документы, поставщики (фото, цены, контакты), калькулятор.
  - `3-profil.html` — профиль: что искать, направление, экономика.
  - `4-uvedomleniya.html` — уведомления о выгодных закупках и всплывающая карточка в углу.
  - `5-razbor-dokumentacii.html` — разбор документации: итог, риски, условия контракта.
  - `6-spravka-i-podskazka.html` — окно справки и всплывающая подсказка «?».

## Главное правило

**Верни только один файл — полный новый `styles.css`.** Разметку (HTML) и скрипты сервиса менять нельзя: страницы собирает JavaScript, и любое переименование сломает сервис.

- Не переименовывай и не удаляй классы и id — оформляй те, что есть в снимках.
- Атрибут `hidden` должен прятать элемент: добавь в начало правило `[hidden] { display: none !important; }`.
- В разметке есть немного встроенных стилей (`style="..."`) — их можно перебить из CSS (при необходимости с `!important`).
- Если для задумки обязательно нужна другая разметка (новый блок, обёртка, иконка), **не меняй HTML сам** — опиши это в конце ответа отдельным списком «Предложения по разметке»: какой элемент, что добавить и зачем. Это сделают отдельно.

## Требования к дизайну

1. **Смысл цветов сохранить** — по ним пользователь принимает решения:
   - выгодно, подходит, низкий риск, «соответствует ТЗ» — зелёный (`--ok`, `--low`, `.econ.good`, `.badge.low`);
   - на грани, возможно, средний риск — жёлто-оранжевый (`--medium`, `.badge.medium`);
   - невыгодно, высокий риск, «не соответствует», ошибка — красный (`--high`, `.econ.bad`, `.badge.high`, `.notice.error`);
   - основной цвет действий — кнопки `.btn.primary`, активная вкладка.
2. **Читаемость прежде всего:** основной текст не меньше 14 px, контраст не ниже WCAG AA, длинные таблицы (позиции ТЗ, поставщики) должны легко читаться построчно.
3. **Адаптивность:** без горизонтальной прокрутки страницы на ширине 375 px (широкие таблицы прокручиваются внутри `.tablewrap`); шапка с вкладками помещается на телефоне.
4. **Тёмная тема — по желанию:** через `@media (prefers-color-scheme: dark)` и переменные в `:root`. Если делаешь — проверь все цвета статусов на тёмном фоне.
5. Шрифты — системные или Google Fonts через `@import`. Без внешних картинок; иконки — только символами/эмодзи, которые уже есть в разметке.
6. Анимации — сдержанные, с `@media (prefers-reduced-motion: reduce)`.

## Основные блоки (что есть что)

- `header`, `nav a`, `nav a.active`, `.bellcount` — шапка, вкладки, счётчик уведомлений.
- `.page`, `.card`, `.notice`, `.notice.error` — страница, карточки-блоки, плашки-пояснения.
- `.btn`, `.btn.primary`, `.btn.danger`, `button.help` (кнопка «?») — кнопки.
- `.badge`, `.econ`, `.trust` — метки статусов, выгодности, доверия к продавцу.
- `table.grid`, `td.n`, `.tablewrap` — таблицы (числа выровнены вправо).
- `tr.tzrow`, `.chars`, `.reqgrid`, `.req`, `.req .rn` — требования ТЗ построчно (название — значение).
- `.pcard`, `.pimg`, `.pspecs`, `.plinks a.buy` — карточка товара у поставщика (фото, характеристики, ссылка «открыть товар»).
- `.contacts` — телефоны, почта, сайт поставщика.
- `.alertrow`, `.alertrow.unread`, `.alertpop` — уведомления и всплывающая карточка.
- `.modal-back`, `.modal` — окна (справка); `.popover` — всплывающая подсказка у кнопки «?».
- `.seg`, `.chips`, `details.sec`, `.savebar` — элементы профиля.

## Формат ответа

1. Полный файл `styles.css` одним блоком кода (не фрагменты, не «остальное без изменений»).
2. Коротко: что изменил и почему (5–10 пунктов).
3. «Предложения по разметке» — если есть.

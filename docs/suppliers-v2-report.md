## Что выполнено из раздела «Важные ограничения» задания

- Интерфейс и уведомления говорят «расчёт по найденным ценам», а не «прибыль подтверждена».
- При ручном выборе предложения с неполной сверкой или ценой старше трёх дней — предупреждение с вопросом; у выбранного — пометка «проверьте». Ручные решения не отменяются.
- Дата цены у каждого предложения показывается отдельно (это уже было в проекте).
- Новых сайтов для обхода модуль не добавляет; сообщения никуда не отправляются; секреты и доступы не менялись; внешние сервисы не подключались.

## Ограничения, которые остаются

- Компании из каталога — кандидаты: юрлица, цены, наличие и условия не проверялись. Партнёрских доступов и ответов API нет.
- Подбор компаний — по направлению товара, а не по наличию модели.
- Если в ТЗ больше 45 требований, сверяются первые 45, и «соответствует» такой товар получить не может. В ленте сейчас 21 такая позиция из 1561.
- Противоречие, которое нейросеть описала своими словами (а не как на странице), теперь считается «не указано», а не «не подходит»: товар покажется «частично», а не «не соответствует». В расчёт сам он всё равно не пойдёт.
- Старые предложения без таблицы сверки (307 на сервере) правило полноты не затрагивает — они остаются как были.
- В списке состояний нет «Не работаем»: скрыть компанию из интерфейса нельзя (через API можно).
- Импорт прайсов и подключение API дистрибьюторов — следующий этап, не делался.

## Как откатить

Код — вернуть состояние до пакета и выложить его:

```bash
git checkout before-suppliers-v2 && bash deploy/deploy-app.sh
```

Структура базы пакетом не меняется, поэтому прежний код работает с той же базой. Вернуть прежний автоматический выбор у изменившихся позиций можно восстановлением базы из копии (служба должна быть остановлена) или повторным поиском по закупке.

Посмотреть все изменения: `git diff before-suppliers-v2 master`.

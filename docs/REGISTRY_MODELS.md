# Модели из реестра для компьютерной техники

ТЗ на ноутбуки, системные блоки, моноблоки и мониторы в госзакупках обычно пишут под реестр российской
промышленной продукции (ПП 719 / ПП 1875). Такому ТЗ соответствуют модели нескольких российских
производителей. Импортные модели из магазинов его, как правило, не проходят.

## Откуда модели

- Реестр gisp.gov.ru закрыт для программ (HTTP 403). Обходить эту защиту нельзя.
- Поэтому модели берутся с сайтов производителей, список — в `config/registry-makers.json`: Гравитон, iRU, Бештау, Крафтвей, Depo, Аквариус.
- Адреса страниц моделей берутся из карты сайта (`sitemap`) или со страниц разделов (`listings`).
- Какие адреса считать моделями, задаёт `product` — регулярное выражение по пути. Подраздел, со страницы которого ведут ссылки на модели глубже его адреса, сам моделью не считается.
- Модуль `server/offers/registry-models.js` хранит модели в `suppliers.db` в таблицах `registry_models` и `registry_makers`.
- Сайты перечитываются раз в `REGISTRY_MAX_AGE_DAYS` дней (по умолчанию 14). Если сайт не ответил, прежние модели остаются.
- Что не попадает в каталог: не компьютеры (мыши, МФУ, серверы, страницы-подборки) и модели «снято с производства».
- Если на странице нет таблицы характеристик, пары «название / значение» берутся с соседних строк текста.

## Подбор под позицию

1. **Вид техники** определяется по наименованию позиции, иначе по коду КТРУ (26.20.11 / 26.20.15 / 26.20.17).
2. **Отбор без нейросети.** Все модели этого вида сверяются по таблице характеристик, справочнику процессоров и числам на странице. Это бесплатно. Явно не подходящие модели отсеиваются, причины видны в блоке.
3. **Сверка нейросетью** по тексту страницы — для лучших `REGISTRY_LLM_TOP` моделей (по умолчанию 6):
   - сначала берётся лучшая модель каждого производителя;
   - если GigaChat не ответил, второй запрос идёт с более коротким текстом.
4. **Требования «по конфигурации»** в отбор не идут: объём памяти и дисков, число накопителей, операционная система. Производитель собирает модель в разных вариантах, поэтому такие требования показаны как «уточнить у поставщика». Модель с ними — не выше «частично».
5. **Хранение итога.** Итог по позиции хранится 7 дней в `settings` (`registry:<id позиции>`).
6. **Связь с поиском поставщиков.** Подошедшие модели («соответствует», «частично») становятся первыми кандидатами при поиске поставщиков:
   - сначала их ищут в своём каталоге страниц — бесплатно;
   - затем поиском Яндекса в пределах обычного лимита запросов на позицию, без дополнительных запросов.

## Интерфейс

- **Где.** Блок «Модели из реестра» стоит в карточке позиции на шаге «Поставщики». Подсказка — `registry_models`.
- **Подбор по кнопке.** `POST /api/tenders/:id/items/:itemId/registry-models`.
- **Состояние каталога.** `GET /api/registry-models`.
- **«Искать продавцов».** Открывает поиск Яндекса в браузере человека — бесплатно.

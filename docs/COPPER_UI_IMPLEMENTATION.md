## Вторая итерация (по скрину макета от владельца, 17.10.2026)

- Вкладка **«Сводка»** — первая и открывается по умолчанию: три суммы из расчёта сделки (цена предложения, плановая прибыль, нужно до оплаты; «оценка», пока цены не подтверждены КП), таблица позиций (фото со страницы продавца или из ТЗ, количество, число предложений, «Проверка»: Выбрать товар / Сверить ТЗ / Нужно КП / Цена по КП), документы из разбора (копии PDF и подписи — числом), полоса «Есть вопросы для проверки» → «Открыть» раскрывает «Помощник».
- **«Помощник»** как в макете: карточки действий (что сделать сейчас, проверки, незавершённые шаги — ведут туда, где человек проверяет; сами ничего не подтверждают), «Вопросы для проверки», «Источники для проверки» (ЕИС — карточка закупки; ЕАТ «Берёзка» — главная страница; РНП — по ИНН выбранного продавца или поиск вручную; картотека дел; разбор), большая кнопка «Проверить расчёт».
- **Верхняя панель**: поиск закупок (текст уходит в поле поиска ленты, на самой ленте скрыт — там своё поле с подсказками), колокольчик с точкой непрочитанных (число — в меню слева).
- Демо: локальный сервер отдаёт подложки (раньше 404 — фото не было видно).

## Отклонения от макета и почему

- Вкладки: «Сводка · Документация · Поставщики · Расчёт · Итог · Заявка» — наши настоящие шаги; отдельной вкладки «Товары» нет, позиции — в «Сводке».
- Пунктов «Обзор» и «Поставщики» в меню нет: таких разделов в сервисе нет (поставщики — внутри закупки). Пустые пункты задание запрещает.
- Имени пользователя вверху нет: в сервисе нет учётных записей.
- «Подтвердить наличие» не ставит отметку нажатием: ведёт на шаг «Расчёт», где подтверждение — с основанием и автором.
- ЕАТ «Берёзка»: известна только главная страница — так и подписано; сервис туда не ходит.
- Подложки на ленте нет: в той карточке фильтры и поля ввода.
- Не проверены вручную: масштаб 200 % и обход всей страницы клавишей Tab.

## Поиск модели на маркетплейсах (ветка `marketplaces`, 17.10.2026)

- Шаг «Поставщики» → блок «На маркетплейсах: та же модель». Модели — только сверенные с ТЗ (модель из ТЗ или товар «соответствует»). Запрос: вид товара + марка + модель («МФУ Катюша M130»).
- «Найти карточки» — 1 запрос к Яндекс Search API на модель (≈0,5 ₽, в суточный лимит `SEARCH_DAILY_MAX_API_REQUESTS`), результат хранится 3 дня; повтор бесплатен. Маркетплейсы сервис не открывает (ни карточки, ни главную — контакты для них тоже не читаются).
- Из выдачи — только карточки товара (Ozon /product/, WB /catalog/…/detail, ЯМ /product, Мегамаркет /catalog/details), модель — целым словом (CF259X ≠ CF259A, M130W ≠ M130, Cactus CS-CF259A ≠ CF259A), не больше 4 с одного маркетплейса; «совместимый/аналог» помечен.
- «Поиск этой модели» — бесплатные ссылки на поиск самого маркетплейса.
- Цена вписывается у карточки → предложение «<Маркетплейс> (маркетплейс)»; для той же сверенной модели — «соответствует» с пометкой, откуда вывод (проверяется на сервере). Ручной выбор пользователя не перебивается.
- Код: `server/offers/marketplaces.js`, `offers.marketplaces()`, маршруты `GET/POST /api/tenders/:id/items/:itemId/marketplaces`; тесты `test/marketplaces.test.js`.
- Живая проверка (локальная копия, 1 запрос ≈0,5 ₽): «МФУ Катюша M130» → 8 карточек Ozon ровно этой модели.
